implemented goal extension or calibrated production accuracy.

extension-configured opt-out, necessary assessment context, and no new approval or
cost-management layer. Concrete settings, supported lifecycle/cancellation hooks,
and complete context assembly remain implementation work; unavailable host features
are omitted rather than turned into mandatory API prerequisites.

:::mara design DES-GOAL-CLASSIFIER-POLICY
:mid: 01M3RWRA7XPRN2AP2S6SQK3Z2S
:title: Bound classifier-first assessments with explicit model profiles and user limits
:status: accepted
:kind: behavior
:satisfies: REQ-GOAL-CLASSIFIERS
:satisfies: REQ-GOAL-EVIDENCE
:satisfies: REQ-GOAL-NO-PROGRESS

Use Pi's native available classifiers, with optional preferred default and supervision/review model overrides and an extension configuration opt-out. No additional approval workflow or code/diff-sharing consent layer is part of this extension. Provide relevant context needed for the assessment by default. Follow the visible deterministic fallback policy in [[REQ-GOAL-CLASSIFIERS]] for unavailable/disabled classifiers, missing applicable model/question profiles and failed/timed-out calls. Fallback must not erase a still-applicable insufficient/uncertain review. Do not create providers, rewrite host settings, or add a classifier client. Preserve model-specific profiles rather than silently advertising the reference model's cutoffs as equivalent calibrated accuracy for other models.

The reference evaluation model is `openrouter/typesafe/jev-1.13`, not the moving latest alias. Its provisional profile uses the returned winning-label probability, not the separate normalized confidence field: supervision requires at least 0.80 for a stuck/blocked label; criteria/evidence review requires at least 0.60 for a sufficient label. Each qualifying label must lead the runner-up by at least 0.30. A weak positive review is uncertain and cannot permit completion. These cutoffs are specific to the evaluated model/questions; changes need evaluation and must not be advertised as equivalent calibrated accuracy. The question templates and observations are retained in [the synthetic records](classifier-evaluation-data.mara.md). Runtime prompt/context adaptation still needs validation. Use only an applicable evaluated model/question profile for classifier decisions. When the selected native model has no such profile, disclose that reason and use deterministic fallback for the feature; do not silently reuse Jev thresholds, select another model contrary to an explicit preference, require provider setup or disable otherwise usable goal work. An available but unprofiled model is not a provider outage.

Run semantic supervision after completed assistant turns while the current goal is active in the selected session/branch, not every nested tool invocation. Cover ordinary user guidance and clarification, initial goal work (including [[REQ-GOAL-CLI-STARTUP]]), automatic continuations, restart-directed work, resume, and manual continue. Follow [[REQ-GOAL-NO-PROGRESS]] for active-interval scope and fresh goal/session revision checks, with no per-message attachment. Exclude other sessions and turns outside that active interval; input origin or failure to repeat the objective is not an exclusion. Known generic-gate waiting is checked directly, not inferred by a classifier. Auto-pause after three consecutive qualifying **new** stuck/blocked observations; cached answers or repeated evaluation of one observation do not advance the streak. Progress and explicit resume reset it; nonqualifying observations cannot form a consecutive qualifying sequence. Pausing does not stop jobs, change gates, or suppress independent delivery. This temporal policy is user-selected and still needs runtime testing; static classification cases do not verify it.

Review acceptance criteria when first created or materially changed before substantive implementation. Review evidence at completion attempts or explicit review requests. Cache ledger reviews against unchanged relevant inputs and classifier configuration, including goal/evidence revision and supplied evidence context; changes invalidate stale results. Configuration changes may invalidate reusable assessments but must not erase an otherwise still-applicable completion veto solely because classification is disabled or its model/profile becomes unavailable. An explicit user-requested re-review may obtain a new assessment, but automatic repeated attempts until one passes are not allowed. When input exceeds a bounded request, use bounded batches and require complete relevant coverage: missing or silently truncated evidence cannot produce approval. A batch's valid refusal must not be discarded because another batch fails. If a request fails or times out and no still-applicable valid refusal exists, use visible deterministic checks instead of requiring a successful classifier response. Missing artifacts, incomplete coverage or unusable assessment data are not transport failures to relabel for this fallback. During every fallback condition, including explicit disablement, a still-applicable insufficient/uncertain review remains a completion veto; no user or model force-complete override is selected. Exact assembly/batch limits remain to be designed and tested.

Use a configurable five-second whole-call timeout, including authentication/request setup, and no extension-added retry loop. Explicitly pass `maxRetries: 0` on every goal classifier call, including supervision, criteria review, and each evidence-review batch; do not rely on the host's agent retry setting or the transport default. This is a per-call option, not permission to rewrite global Pi/provider settings. Distinct bounded batches and explicit re-review remain governed by cadence and caching, not an automatic retry-until-success loop. Verify supported transports honor the zero-retry option. Deadline expiry is not proof that an uncooperative provider stopped or that a failed request was free; late-result, activity and incomplete-usage handling still need runtime design. The user subsequently removed classifier-specific spending limits and cost-management requirements. Do not build hourly/total monetary caps, price admission, reservations, cost-driven fallback, or a separate reconciliation subsystem. Use ordinary supported native usage reporting where available; missing pricing or usage is not zero, but it is not an execution gate. Omit unsupported host accounting features with an honest limitation instead of making a new SDK API mandatory. Optional explicitly configured whole-goal token/wall-time limits remain separate.

Inputs include the relevant goal context and inspected code, diff, or test-output excerpts needed for the assessment, subject to native context limits and complete-coverage batching, not an entire transcript or automatic retrieval of every referenced artifact. No extra approval or excerpt opt-in is required; the extension's classifier-disable flag is the opt-out. Inputs remain transient; persist bounded diagnostics and references, not raw evidence. Check availability before requests and reject stale results after goal/evidence/session changes. Valid refusals for unchanged goal/evidence survive later outages; no force-complete bypass is provided. Users can revise evidence, explicitly re-review, pause, or clear the goal. A refusal should cause the agent to repair implementation/evidence or clarify criteria without weakening acceptance criteria, subject to blockers, supervision and budgets. See [[REQ-GOAL-EVIDENCE]].
