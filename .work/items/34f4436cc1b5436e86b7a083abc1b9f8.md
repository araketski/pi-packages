## Observable acceptance

Use actual persistent/in-memory Pi sessions and controlled executors. Verify same-session idle/reload preserve execution through fresh public callbacks, while new/switch/fork replacement triggers bounded best-effort owned cancellation without indefinitely blocking replacement. Unconfirmed cleanup stays honest; late callbacks/results do not use stale capabilities or wake another session. Reopen only already-saved metadata/results, defer saved pending results until the next user message, and never treat saved running state as liveness or restart/adopt historical executions. Tree does not rewind execution, forked history transfers references not authority, and no-session has no post-exit promise. Inactive completion capture/delivery and crash/forced-kill cleanup/recovery are outside scope. Exercise automatic/next-turn/display-only delivery, batching, foreground/retrieval/automatic races, recorded rather than queued receipts, and stable-identity redelivery without execution reruns. Gate state follows owner obligations, with no consumer-purpose or producer-specific logic. Preserve inactive tracked gate reasons needed by caffeinate through the public gates boundary; coordinate any generic protocol fixes rather than teaching consumers about jobs.

Implement completion-inbox delivery under REQ-JOBS-COMPLETION-INBOX and run the representative overlapping-job, retrieval and ambiguous-receipt cases in VER-JOBS-DELIVERY; exhaustive five-job interleaving campaigns are deferred. Verify one pending wake per originating session across producers/core copies, no interruption while waking/working, idle-boundary reconciliation, and selected-result receipt arbitration. Define the public Pi queue mapping and document unsupported suppression cases rather than using private state or adding a scheduler. Existing delivery-mode, resume and non-UI policies remain in force; this does not add child-assignment tracking.
